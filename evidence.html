评测与治理 ·不同诊断路径，如何被分别验证

统一质量底座 · 分路径指标 · 可回放迭代

光溯不是让所有问题都走同一条 Agent Workflow。业务场景深诊断、领域 Agent 问答和日志检索使用不同路径，也必须用不同指标判断质量。

按路径分别评测基准契约工具调用与证据链路评测判定结果失败样本回流

质量判断

先区分评测对象，再验证执行、证据、边界与回归

领域问答、日志检索和业务深诊断具有不同目标。按路径分别评测让每个失败都能指向明确的能力层与修复责任。

01 / ROUTE路径选择

验证领域路由、深诊断升级与任务创建是否符合入口边界。

02 / EVIDENCE证据充分性

验证回答或结论能否指回知识引用、日志片段、工具结果与业务链路。

03 / BOUNDARY结论边界

证据不足时保留候选原因、正确拒答或转交人工，避免强行归类。

04 / REGRESSION版本回归

知识、模型、工具或流程变更后，固定样本按各自路径稳定回放。

路径与评测

三类入口，四种实际执行方式

业务场景深诊断是端到端趋势跟踪的主对象；领域 Agent 与日志检索保留自己的目标和质量口径。

PATH 01 · PRIMARY

业务场景深诊断

链路最长、证据源最多，形成完整诊断任务与报告。

请求理解→场景解析与确认→读取业务链路→日志 + RAG + 条件诊断→证据约束报告

应用、系统、网络问题进入受控领域智能体，结合 RAG 与按需工具补充上下文。

PATH 03 · RETRIEVAL

日志检索

技术用户已提供结构化条件，跳过前置自然语言理解。

按业务场景读取已维护链路 → 多节点日志 → 证据选择
按应用 / 节点直接查询日志 → 异常片段 → 证据选择
→可选生成诊断任务
独立评测指标
检索条件有效链路或节点覆盖日志召回有效证据选择质量任务生成成功
评测规则：不同路径分别评测、分别归因，不混算一个“全链路准确率”；业务场景深诊断默认承担端到端回归与版本趋势。
统一质量底座

路径不同，但证据、工具和版本仍需共同治理

四层模型是横向质量框架，不代表每条路径都必须走完四层；每条路径按自身风险选择评测深度。

LAYER 01知识与回答层

检查候选命中、上下文精度、回答忠实度、引用有效性与知识来源。

LAYER 02工具与数据层

检查参数、执行状态、结果回传，以及链路、节点和日志数据是否真实可用。

LAYER 03路径与结论层

检查跨层路由、证据合并、条件分支、拒答升级与结论门禁。

LAYER 04发布与回归层

检查匿名边界、版本冻结、Runner 可回放性和历史样本退化。

代表案例契约

把业务深诊断的产品判断编码成 10 项门禁

“RPC 超时不能直接写成网络根因”不是文案偏好，而是可自动执行、可失败、可回归的产品边界。

以下契约用于公开主案例的业务场景深诊断路径。

业务场景深诊断 · 10 项
01 / PATH路径顺序

实际步骤与签核路径一致。

02 / EVIDENCE必备证据

日志、服务和网络证据齐全。

03 / TOOL服务工具

存在可审计的工具调用记录。

04 / TOOL网络工具

探测调用与结果进入 Trace。

05 / ROUTE跨层路由

网络触发，数据库保持跳过。

06 / REPORT报告引用

结论覆盖必备证据。

07 / GUARDRAIL禁止断言

不把 RPC 超时直接写成网络根因。

08 / RETRIEVAL检索可用

RPC 排查知识真实可用。

09 / BOUNDARY结论强度

根因限定在匿名 fixture。

10 / REGRESSION接口回归

正例与失败门禁全部通过。

知识治理

三类路径共享一套可追溯的知识与证据资产

路径拆分不等于数据割裂；业务拓扑、日志、领域知识和处理经验仍需统一对象、来源、责任和版本。

12个业务与技术团队

协调知识贡献、责任确认和更新边界。

01统一知识对象

业务场景、应用节点、接口、错误码、日志入口和处理经验。

02补齐治理字段

来源、版本、责任域、适用环境、敏感级别和失效状态。

03建立关系层

把场景、应用、接口、日志、工具和责任域连成上下文。

04动态更新

变更经确认后发布，并触发受影响路径的样本回归。

知识命中 ≠ 根因确认

检索结果只提供排查方向，业务深诊断仍需运行证据。

检索失败 ≠ 知识缺失

召回问题、路由问题与知识缺口需要分开归因。

动态更新 ≠ 自动入库

来源、范围、责任和受影响路径确认后才能发布。
